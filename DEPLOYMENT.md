# Coraxis — Deployment Guide

Coraxis is **two services**. Deploying only the frontend (the previous
Vercel-only state) leaves sign-in and every API call broken:

- The Next.js app proxies `/api/v1/*` to `CORAXIS_BACKEND_URL`
  (default `http://127.0.0.1:8000` — on Vercel that is Vercel itself, so
  every API call fails unless the variable is set at build time).
- Sign-in needs **either** Firebase **or** nothing extra: when the
  `NEXT_PUBLIC_FIREBASE_*` variables are absent, the app now falls back
  to the backend's own email/password accounts (`/auth/register`,
  `/auth/login`). GitHub sign-in is the only feature that requires
  Firebase.

## 1. Backend API (Render, Fly.io, a VPS — anywhere Docker runs)

This repo ships a `Dockerfile` and a `render.yaml` blueprint.

On Render: **New → Blueprint → connect this repo**. Then set:

| Variable | Value |
|---|---|
| `CORAXIS_SECRET_KEY` | Auto-generated by the blueprint, or `python -c "import secrets; print(secrets.token_urlsafe(64))"` |
| `CORAXIS_CORS_ORIGINS` | Your frontend origin, e.g. `https://your-app.vercel.app` |
| `CORAXIS_FIREBASE_PROJECT_ID` | Optional — only for Firebase/GitHub sign-in. Existing project id: `coraxis-3c882` (see `.firebaserc`) |
| `CORAXIS_ALLOW_REGISTRATION` | `true` until your account exists, then `false` |

Notes: run **one worker only** (run/event state and the rate limiter are
in-process). SQLite is stored in the container at `/data` — mount a
persistent disk there, or set `CORAXIS_DATABASE_URL` to Postgres
(`postgresql+asyncpg://…`, install the `postgres` extra / use
`docker-compose.yml` locally as a reference).

Verify: `GET https://<your-api>/health` → `{"status":"healthy",…}`.

## 2. Frontend (Vercel)

Project settings:

- **Root Directory:** `frontend`
- **Framework Preset:** Next.js

Environment variables (Project Settings → Environment Variables), then
**redeploy** — `NEXT_PUBLIC_*` and `CORAXIS_BACKEND_URL` are read at
build time, so changing them without a redeploy changes nothing:

| Variable | Required | Value |
|---|---|---|
| `CORAXIS_BACKEND_URL` | **Yes** | Public URL of the backend from step 1, e.g. `https://coraxis-api.onrender.com` |
| `NEXT_PUBLIC_FIREBASE_API_KEY` | Only for GitHub sign-in | Firebase console → Project settings → General → Your apps → Web app config |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | " | `<project>.firebaseapp.com` |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | " | e.g. `coraxis-3c882` |
| `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` | " | `<project>.appspot.com` |
| `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID` | " | From the same config snippet |
| `NEXT_PUBLIC_FIREBASE_APP_ID` | " | From the same config snippet |

### If you enable Firebase / GitHub sign-in

1. Firebase console (project `coraxis-3c882`) → Authentication →
   Sign-in method → enable **Email/Password** and **GitHub**
   (GitHub needs an OAuth app's client id/secret from GitHub Settings →
   Developer settings → OAuth Apps, with callback
   `https://coraxis-3c882.firebaseapp.com/__/auth/handler`).
2. Authentication → Settings → Authorized domains → add your Vercel
   domain.
3. Project settings → General → Your apps → add a **Web app** if none
   exists, and copy its config into the Vercel variables above.
4. Set `CORAXIS_FIREBASE_PROJECT_ID=coraxis-3c882` on the **backend**
   too — it verifies Firebase ID tokens against that project.
5. Redeploy both services.

Without steps 1–5 the app still works: the sign-in screen hides the
GitHub button and uses Coraxis server accounts instead of showing
"Firebase is not configured".

## 3. Smoke test after deploying

1. Open the site → sign-in screen shows **no** red Firebase banner.
2. Create one (email + password, min 12 chars) → you land in the app;
   the first account is the administrator.
3. Settings → add a provider key (Groq/Gemini/OpenAI) → run a research
   question → events stream and a cited report appears.
